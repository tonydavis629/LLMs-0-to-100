## In-Context Learning in Applications

In-context learning: the model picks up a task from examples in its prompt, with no gradient update.

:::columns cols="2" gap="34px"
**In Module 5**

- GPT-3 measured it with few-shot benchmarks
- It was evidence that scale had produced a new ability
+++
**In this module**

- It is how applications get built
- A prompt states the task, the output format, some examples, and the constraints
- The weights stay fixed
:::

## Zero-Shot and Few-Shot

<div class="card-grid cols-2">
<div class="card"><h4>Zero-shot</h4><p>A task description and nothing else: "Classify this review as positive or negative." The model has to infer the format and the edge cases from the description.</p></div>
<div class="card"><h4>Few-shot</h4><p>A description plus worked examples. A few examples usually pin down the format and the edge cases better than more instructions do.</p></div>
</div>

Module 9 showed that the number of shots changes benchmark scores on identical weights. If the model gets the format wrong, add an example before adding more instructions. <!-- .element: class="text-lg" style="margin-top: 12px;" -->

## The System Prompt

An application has two authors: the developer and the user.

- The **system prompt** is the developer's channel. It holds instructions, persona, rules, and context the user never sees
- The chat template (Module 6) marks which text came from whom

<div class="metric-box">
<p><code>&lt;|system|&gt;</code>, <code>&lt;|user|&gt;</code>, and <code>&lt;|assistant|&gt;</code> are special tokens. The model follows the system prompt over the user because it was <strong>finetuned</strong> on conversations where the system instructions win.</p>
</div>

Nothing in the architecture enforces that ordering. Adversarial text can override it, and prompt injection (later in this module) does exactly that. <!-- .element: class="text-lg" -->

## Chain-of-Thought Prompting

Wei et al. (2022): ask for **intermediate steps** before the answer, and accuracy on multi-step problems goes up.

- Few-shot version: the examples show worked reasoning
- Zero-shot version (Kojima et al., 2022): append "Let's think step by step"

:::columns cols="2" gap="34px"
**Why it helps**

- Each generated step becomes context for the next token
- The model reaches the answer through many small predictions
+++
**Relation to Module 7**

- Reasoning models have chain-of-thought trained **into the weights** by RL
- Prompted chain-of-thought happens at inference time and works on any instruct model
:::

Jason Wei also built FLAN (Module 6). <!-- .element: class="text-lg" style="margin-top: 10px;" -->

## What Prompting Cannot Do

Prompting changes **how** the model behaves. It does not change **what the model knows.**

<div class="metric-box">
<p>A prompt cannot supply a fact the model never saw in training, unless the fact is written in the prompt. Yesterday's outage, your internal wiki, and a customer's order history are not in the weights.</p>
</div>

## <span class="side-quest-badge">Side Quest</span> Why Does In-Context Learning Work?

The weights do not change during few-shot prompting, so where does the learning happen?

:::columns cols="2" gap="34px"
**Induction heads**

- Olsson et al. (2022, Anthropic) found pairs of attention heads that locate an earlier occurrence of the current pattern and **copy what came next**
- Given "A: 1, B: 2, A:", the head attends back to "A: 1" and raises the probability of "1"
+++
**What makes them interesting**

- Nobody designed them. They are Module 3's attention, learned by gradient descent
- They form early in training, at almost any model size
- In-context learning ability jumps at the same point in training
:::
